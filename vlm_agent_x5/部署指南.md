# RDK X5 仪表图像 Agent：逐条部署

此目录是新增交付；YOLO原代码、模型及[队友板端手册](../deployment/rdk_x5/README.md)保持原样。每次只处理一张图片：CPU ONNX YOLO读表 → RDK X5 InternVL2.5-1B观察 → JSON留档。当前BPU版YOLO `.bin` 尚未编译及验收，也未接入数值后处理；此入口调用队友的 `tools/run_onnx.py`，因此**YOLO是在CPU上使用ONNX Runtime**。板端速度、ARM依赖兼容和VLM输出质量仍须在真实X5上验证。

依据：[D-Robotics官方InternVL X5文档](https://developer.d-robotics.cc/rdk_doc/en/rdk_s/Robot_development/boxs/generate/hobot_llamacpp/) 指定X5 Ubuntu 22.04、TogetheROS.Bot、`tros-humble-hobot-llamacpp`、ION 1.6GB，以及配套 `vit_model_int16_v2.bin` 和 `Qwen2.5-0.5B-Instruct-Q4_0.gguf`。文档的终端图片模式使用 `ros2 run hobot_llamacpp hobot_llamacpp --ros-args -p feed_type:=0 -p image:=... -p image_type:=0 -p user_prompt:=... -p model_file_name:=... -p llm_model_name:=...`；本适配器按此调用，并从终端输出提取JSON。官方页面提示已迁至新版资源中心，实际上板前仍需核对板端包与文档版本。

1. RDK X5烧录Ubuntu 22.04，安装TogetheROS.Bot。按官方说明在板上运行：

   ```bash
   sudo apt update
   sudo apt install tros-humble-hobot-llamacpp python3-venv wget
   ```

2. 在板上运行 `srpi-config`，将ION内存设为1.6GB、CPU频率设为最高，并按界面提示重启。确认安装完成：

   ```bash
   source /opt/tros/humble/setup.bash
   ros2 pkg executables hobot_llamacpp
   ```

3. 将已推送的 `VLM` 分支克隆至板端（推送前可用离线复制，不要假称远端已有VLM）：

   ```bash
   git clone https://github.com/19820960710/meter-identification.git
   cd meter-identification
   git switch VLM
   ```

4. 为队友当前CPU ONNX读数入口安装Python依赖。使用板端Python环境；ARM下 `onnxruntime`/OpenCV wheel 能否安装和运行要实测：

   ```bash
   python3 -m venv .venv-x5-agent
   source .venv-x5-agent/bin/activate
   python -m pip install -r vlm_agent_x5/requirements.txt
   python tools/verify_bundle.py
   ```

5. 另行下载**X5专用**视觉 `.bin` 和配套 `.gguf`（模型文件存 `vlm_agent_x5/models/`，被git忽略）：

   ```bash
   bash vlm_agent_x5/下载模型.sh
   ls -lh vlm_agent_x5/models/
   ```

6. 打开 `vlm_agent_x5/config.json`，核对CPU ONNX模型、两份X5模型、超时和输出目录。先用已做图片SHA绑定标定的样图：

   ```bash
   python vlm_agent_x5/启动.py --image samples/images/0.jpg
   ```

   或用输入JSON（`input.example.json`展示格式；将图片改为真实绝对路径）：

   ```bash
   python vlm_agent_x5/启动.py --request vlm_agent_x5/input.example.json
   ```

7. 终端会打印结果路径，例如 `vlm_agent_x5/outputs/20261103_120000_abcd1234/result.json`。同目录 `yolo/result.json` 和检测叠图来自队友CPU ONNX程序；`vlm_stdout.log`、`vlm_stderr.log` 保留ROS原话；`agent.log` 保留错误。`result.json` 的四项是仪表类型、YOLO原值和单位、图像可核对性、表盘可见状态；VLM失败时状态为 `partial`，仍留存YOLO结果。

**多表和标定边界：** 程序只在当前图片SHA匹配已有标定、YOLO读出数值且检测到唯一目标表盘时标为“可供图像核对”。没有对应标定、多个目标候选或仅检测未读数时一律“待复核”。同一张图即使VLM描述另一块表，程序也不会把它的说法改写为YOLO原值。新拍图片的SHA不同，不能套用旧图像素标定。图像观察只负责可见问题，不生成设备工作范围或安全结论。

**尚未板端验证：** 两份模型文件的实际下载、`hobot_llamacpp`参数与终端输出格式、ROS节点退出行为、ARM CPU ONNX安装和速度、YOLO/VLM联合运行耗时、视觉结论。若ROS终端没有输出可解析的四字段JSON，Agent按超时或格式失败保存原始日志和YOLO结果，需按实际板端软件版本修正适配器；不会伪造成功。
