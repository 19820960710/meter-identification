# RDK X5 板端 VLM Agent：逐步部署与试跑

本目录只有一个中文入口 `启动.py`。流程是图片 → 队友现有CPU ONNX YOLO → 若检出表盘则让InternVL2.5-1B观察目标表盘，否则让它观察整张现场图 → 保存JSON和日志。支持单图与持续监听文件夹，按`0`回车或`Ctrl+C`退出监听。

**状态说明：本版已完成PC侧代码检查和YOLO样图试跑，尚未在真实X5上完成ROS话题、VLM模型和持续运行的端到端验收。**以下是板端试跑步骤，出现错误时按顺序定位，不应跳过步骤。队友[main分支部署说明](../deployment/rdk_x5/README.md)指出其YOLO BPU `.bin`和板端数值后处理尚未验收，本Agent实际调用的是`tools/run_onnx.py`及ONNX Runtime **CPU**，不调用YOLO BPU推理。

VLM的模型组合、系统环境和ROS参数以[D-Robotics X5 InternVL2.5-1B文档](https://developer.d-robotics.cc/rdk_doc/en/rdk_s/Robot_development/boxs/generate/hobot_llamacpp/)为依据。Agent从`ai_msgs/msg/PerceptionTargets`的`targets[].type`读取最终回答，依据[核查时的官方hobot_llamacpp源码](https://github.com/D-Robotics/hobot_llamacpp/blob/439f23f6c9b09eaebcf84027a0911c220fb4fb34/src/llamacpp_node.cpp)；每张图片使用一个专用话题，避免串图。现场场景资料仅提供一般检查方向，不代替现场规程。

## 1. 准备板卡系统

1. 使用RDK X5、Ubuntu 22.04和TogetheROS.Bot。先执行：

   ```bash
   uname -m
   python3 --version
   sudo apt update
   sudo apt install git python3-venv wget tros-humble-hobot-llamacpp
   srpi-config
   ```

   在`srpi-config`里把ION设为1.6GB、CPU设为最高频率，按界面提示重启。具体菜单以板卡镜像版本为准。重启后执行：

   ```bash
   source /opt/tros/humble/setup.bash
   ros2 pkg executables hobot_llamacpp
   /usr/bin/python3 -c 'import rclpy; from ai_msgs.msg import PerceptionTargets; print("ROS消息依赖可用")'
   ```

   第二条应列出`hobot_llamacpp`可执行文件；第三条应打印“ROS消息依赖可用”。失败时先检查系统镜像和ROS包来源。Agent的YOLO虚拟环境与ROS系统Python是两个独立环境。

## 2. 把VLM分支带到板上

2. **本地VLM分支尚未推送远程。**当前可以通过U盘、局域网传输等方式，把本地`YOLO_Agent`仓库完整复制到板上，进入仓库根目录；若以后经允许把`VLM`分支上传，才可改用：

   ```bash
   git clone https://github.com/19820960710/meter-identification.git
   cd meter-identification
   git switch VLM
   git rev-parse --short HEAD
   ```

   离线复制的目录必须同时有`tools/run_onnx.py`、`configs/gauges/`、`deployment/rdk_x5/README.md`和`vlm_agent_x5/`。不能只下载远程`main`，因为那里还没有本Agent。若复制了`.git`，可用`git branch --show-current`核对为`VLM`。

3. 按队友main分支文档检查文件和系统信息：

   ```bash
   python3 tools/verify_bundle.py
   mkdir -p outputs
   python3 tools/probe_rdk.py > outputs/rdk-environment.json
   cat outputs/rdk-environment.json
   ```

   这只是交付和板卡检查，不代表VLM推理已经成功。队友文档里的YOLO BPU编译流程是独立试验，本Agent目前不依赖该`.bin`。

## 3. 安装并验证CPU YOLO

4. 在仓库根目录执行：

   ```bash
   python3 -m venv .venv-x5-agent
   source .venv-x5-agent/bin/activate
   python -m pip install -r vlm_agent_x5/requirements.txt
   python -c 'import numpy, cv2, onnxruntime; print("YOLO Python依赖已导入")'
   python tools/run_onnx.py --image samples/images/763.jpg --output outputs/cpu-detect
   python tools/run_onnx.py --image samples/images/0.jpg --profile configs/gauges/photo_fae0688c1fa78bd7.json --output outputs/cpu-read
   cat outputs/cpu-read/result.json
   ```

   763号图验证无标定时的检测路径；0号图用其**同图SHA**标定验证CPU读数路径。`result.json`应如实显示`backend: onnxruntime_cpu`。若板卡ARM环境无法安装OpenCV或ONNX Runtime wheel，先解决对应Python版本与架构的依赖，不得把未验收的YOLO BPU路径写成已接通。新拍图片与样图SHA不同，不能自动套用旧图像素标定，可能只返回检测而没有可确认的数值。

## 4. 下载X5 VLM模型，先跑官方示例

5. 在仓库根目录下载配套模型：

   ```bash
   bash vlm_agent_x5/下载模型.sh
   ls -lh vlm_agent_x5/models/vit_model_int16_v2.bin
   ls -lh vlm_agent_x5/models/Qwen2.5-0.5B-Instruct-Q4_0.gguf
   sha256sum vlm_agent_x5/models/vit_model_int16_v2.bin vlm_agent_x5/models/Qwen2.5-0.5B-Instruct-Q4_0.gguf
   ```

   `.bin`是X5视觉编码器，`.gguf`是配套语言模型。二者必须成对；PC端Transformers权重和S100的`.hbm`不适用。模型被`vlm_agent_x5/.gitignore`排除，不随Git提交。记录文件大小及SHA256；下载不完整时重新下载。自检会拒绝小于1MB的模型文件，但仍需核对下载来源与实际文件大小。

6. **先绕过Agent，用官方ROS命令验证模型**。开两个板端终端，都执行`source /opt/tros/humble/setup.bash`。终端A执行：

   ```bash
   ros2 topic echo /llama_cpp_node ai_msgs/msg/PerceptionTargets
   ```

   终端B进入仓库根目录后执行：

   ```bash
   ros2 run hobot_llamacpp hobot_llamacpp --ros-args \
     -p feed_type:=0 -p "image:=$(pwd)/samples/images/0.jpg" -p image_type:=0 \
     -p 'user_prompt:=请简短描述图中的仪表' \
     -p "model_file_name:=$(pwd)/vlm_agent_x5/models/vit_model_int16_v2.bin" \
     -p "llm_model_name:=$(pwd)/vlm_agent_x5/models/Qwen2.5-0.5B-Instruct-Q4_0.gguf"
   ```

   终端A应收到`targets`，其中`type`包含最终回答。此命令使用绝对图片和模型路径，不依赖官方示例的`config/image2.jpg`。若无法收到，先检查ION、ROS环境、包、模型配对与终端B日志；先让官方单图示例成功，再运行Agent。按`Ctrl+C`结束两个终端的试验。

## 5. 自检、单图和持续监听

7. 重新进入仓库根目录、激活YOLO虚拟环境，执行Agent自检：

   ```bash
   source .venv-x5-agent/bin/activate
   python vlm_agent_x5/启动.py --check-env
   cat vlm_agent_x5/outputs/环境检查.json
   ```

   `ready=true`表示文件、Linux ARM64、CPU YOLO依赖、ROS可执行文件、系统Python的`rclpy`和`ai_msgs`消息类型均通过静态检查，**不等于推理已经成功**。`ready=false`返回退出码2，逐项查看`checks`。自检不会安装、下载或更改板卡配置；ION、CPU频率和真实耗时需人工确认。

8. 单图体验：

   ```bash
   python vlm_agent_x5/启动.py --image samples/images/0.jpg
   ```

   该图有同图SHA标定，应走仪表分支。再用实际无仪表图片测试场景分支：

   ```bash
   python vlm_agent_x5/启动.py --image /absolute/path/to/no_meter_scene.jpg
   ```

   也可把`vlm_agent_x5/input.example.json`里的`image`改成板端图片**绝对路径**，运行`python vlm_agent_x5/启动.py --request vlm_agent_x5/input.example.json`。YOLO运行失败不会被当成“现场无表”。多表图无法唯一关联读数时标为“待复核”。

9. 持续检测文件夹：

   ```bash
   mkdir -p incoming_images
   python vlm_agent_x5/启动.py --watch-folder incoming_images
   ```

   把`jpg`、`jpeg`、`png`、`bmp`或`webp`放入该目录第一层即可。程序默认每秒扫描，文件大小和修改时间连续1.5秒不变后才处理；可加`--poll-seconds 2 --stable-seconds 3`调整。同一路径同一内容在本次监听中只处理一次，覆盖为新内容则重做；重启监听会处理目录中已有图片。程序串行处理，VLM每张图重新启动，实际处理速率需在板上测量。输入`0`回车可在当前图处理完后退出；`Ctrl+C`可中断。

## 6. 结果位置与排错

10. 单图输出位于`vlm_agent_x5/outputs/<时间_编号>/`。`result.json`为汇总结果；同目录还有原图快照、`input.json`、`yolo/result.json`、`yolo_stdout.log`、`yolo_stderr.log`、`vlm_request.json`、`vlm_stdout.log`、`vlm_stderr.log`、`vlm_topic_stderr.log`和`agent.log`。如果收到最终话题回答，`vlm_topic.json`记录原话；`result.json`的`vlm.raw_answer`也保留原话。场景分支另有`scene_sources.json`，仪表分支可能有`target_dial.png`。监听会话目录`outputs/watch_<时间_编号>/`内有`watch_session.json`和`watch.log`，记录每张图的SHA、状态和结果路径。

11. `status=completed`表示程序收到了符合格式的VLM回答；`partial`表示YOLO结果保留，但VLM失败或读数不足；`failed`表示上游关键步骤失败；`interrupted`表示手动中断。遇到`partial`，先看`result.json`的`errors`和`vlm`：

   - 报缺少模型文件：返回第4节下载和核对路径。
   - `vlm_topic_stderr.log`报`rclpy`或`ai_msgs`导入失败：返回第1节检查系统ROS。
   - `vlm.raw_answer=null`：未收到最终话题，查看`vlm_stderr.log`与`vlm_stdout.log`，检查节点是否启动或超时。
   - `vlm.raw_answer`有内容、`candidate=null`：模型没有按提示词生成可解析JSON；原话已保留，可据实际输出调整解析或提示词。
   - 有`candidate`但校验失败：查看`agent.log`；YOLO原始读数不会被VLM覆盖。

   `config.json`中的相对路径都以`vlm_agent_x5/`为基准。默认`timeouts.yolo_seconds=120`、`timeouts.vlm_seconds=180`；如果板端真实模型加载和推理超过180秒，可在试跑记录实际耗时后增大后者。`output.schema.json`、`input.schema.json`及两个`*.example.json`给出输入输出格式。

- 保存`outputs/rdk-environment.json`、ROS包/系统版本、ION配置、两个VLM模型的大小和SHA256、自检JSON。
- 用同一张已标定样图对比板端CPU ONNX和电脑结果；新图片没有同图标定时不得伪造读数。
- 分别保存一张仪表图和一张无表场景图的`result.json`、ROS原话、YOLO检测框与耗时；再进行多图持续监听和手动退出测试。
- 若官方单图命令或本Agent任一环节失败，保留原始日志和`partial/failed`状态，不宣称完整板端链路通过。场景隐患文本需由现场人员复核，不能当作安全认证。

**电脑侧已知结果：**原入口曾用0号真实样图得到CPU ONNX读数约0.3776 MPa，因PC没有X5模型和ROS包，VLM被记录为`partial`；监听记录正常留档。新的ROS话题接收代码仅能在PC进行语法、解析和模拟检查，实际X5推理与时延仍待板端验证。
